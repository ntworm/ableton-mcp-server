## A. The dispatch pattern we already have

For reference — every new handler must follow this pattern. Code is in `AbletonMCPServer_RemoteScript/__init__.py`:

```python
COMMAND_HANDLERS: dict[str, CommandHandler] = {
    "get_session_info": cmd_get_session_info,
    "create_clip": cmd_create_clip,
    # ... ~30 entries ...
}
```

**Handlers are SYNC functions** with signature `(song, _application, params) -> dict`, NOT generators. Deferred verification is encapsulated in `_verified_*_steps` helpers which are generator helpers that **get yielded** only when needed:

```python
def cmd_create_clip(song, _application, params):
    track_index = _integer_param(params, "track_index")
    clip_index = _integer_param(params, "clip_index")
    length = _float_param(params, "length_beats", 0.0, 100000.0, strictly_positive=True)
    track, slot = _clip_slot(song, track_index, clip_index)
    if _track_type(song, track) != "midi":
        raise RemoteError(ERROR_WRONG_TYPE, "create_clip requires a MIDI track.")
    if bool(_safe(lambda: slot.has_clip, False)):
        raise RemoteError(ERROR_BAD_INPUT, "Clip slot is not empty.")
    slot.create_clip(length)
    return {
        "created": True,
        "clip_id": "track:%s/clipslot:%s/clip" % (track_index, clip_index),
        "length_beats": length,
    }
```

For mutations that need **deferred verification across UI ticks**, dispatch through `_dispatch_command_steps` (which has 4 special cases: `run_batch`, `create_cue_point`, `bulk_create_cue_points`, `delete_cue_point`, `set_current_song_time`) plus the generic ones that call `yield from _verified_*_steps(song, ...)`.

**Available reusable helpers** (do not reimplement):

| helper | what | reuse for |
|---|---|---|
| `_safe(getter, default)` | swallows `AttributeError`/`RuntimeError`/`TypeError` | attribute reads that may not exist in older Live |
| `_required(params, name)` | missing-key → `ERROR_INVALID_PARAMS` | all new commands |
| `_integer_param(params, name, minimum=0)` | type-checked int, ≥ minimum | all new commands |
| `_float_param(params, name, minimum, maximum=None, strictly_positive=False)` | `NaN`/inf → `ERROR_BAD_INPUT`, finite check, range check | all new commands |
| `_string_param(params, name)` | non-empty, stripped | all new commands |
| `_all_tracks(song)` | regular + return + master | all new commands |
| `_track_at(song, index)` | alias for `_all_tracks(song)[index]`, raises if OOR | track commands |
| `_track_type(song, track)` | "midi" / "audio" / "return" / "master" | clip/track type checks |
| `_clip_slot(song, track_idx, clip_idx)` | `(track, slot)` tuple | ALL clip commands |
| `_verified_boolean_steps(song, *, attribute, expected, setter, result_key)` | retry until attr matches expected, 10 ticks, raise `ERROR_LIVE_UNAVAILABLE` | `set_track_property` for mute/solo/arm |
| `_verified_numeric_steps(song, *, attribute, expected, result_key)` | same, for float | `set_clip_properties` loop_start/loop_end |
| `_verified_playhead_steps(song, target)` | suspends `clip_trigger_quantization`, 10 retries | already used |
| `_begin_undo(target)` / `_end_undo(target)` | raises `ERROR_LIVE_UNAVAILABLE` if host doesn't expose | already wrapped by `_command_steps` |

**Undo is automatic** when a command is in `ALLOWED_MUTATIONS`. `_command_steps` calls `_begin_undo(target)` before dispatch and `_end_undo(target)` in `finally`. Do **not** manually open/close undo in your handler — let the framework handle it. Exception: `run_batch` opens one outer step and dispatches children with `manage_undo=False`.

**Existing `cmd_*` shape (canonical template):**

```python
def cmd_create_clip(song, _application, params):
    track_index = _integer_param(params, "track_index")
    clip_index = _integer_param(params, "clip_index")
    length = _float_param(params, "length_beats", 0.0, 100000.0, strictly_positive=True)
    track, slot = _clip_slot(song, track_index, clip_index)
    if _track_type(song, track) != "midi":
        raise RemoteError(ERROR_WRONG_TYPE, "create_clip requires a MIDI track.")
    if bool(_safe(lambda: slot.has_clip, False)):
        raise RemoteError(ERROR_BAD_INPUT, "Clip slot is not empty.")
    slot.create_clip(length)
    return {"created": True, ...}
```

Three new commands (`delete_clip`, `clear_clip_notes`, `fire_scene`, `get_clip_info`) fit this template as-is. `set_track_property` reuses `_verified_boolean_steps`. Only `set_clip_properties` (multi-property) and `create_clip_automation` (envelope write) need custom deferred logic.

**Then in `server.py`:**

```python
@mcp.tool()
def create_cue_point(name: str, time: float) -> Any:
    return _remote("create_cue_point", models.CreateCuePointRequest(name=name, time=time))
```

And in `PUBLIC_TOOL_NAMES`, and `models.py` (Pydantic). Every new tool follows this shape. Mechanical.

### B2. `clear_clip_notes(track_index, clip_index)` — AB-2

**Source:** `hidingwill/AbletonBridge`, `AbletonBridge_Remote_Script/handlers/clips.py` (via `remove_notes_extended` strategy) and `MCP_Server/tools/clips.py:clear_clip_notes`.

**Their signature:**

```python
def clear_clip_notes(ctx: Context, track_index: int, clip_index: int) -> str
# Returns "Cleared {notes_removed} notes from clip..."
```

**Our signature (sync):**

```python
@mcp.tool()
def clear_clip_notes(track_index: int, clip_index: int) -> Any:
    """Remove all MIDI notes from a clip without deleting it.
    
    Side effects: clears the clip in one undo step. Clip itself remains.
    Edge cases: audio clips return WRONG_TYPE.
    """
    return _remote(
        "clear_clip_notes",
        models.ClearClipNotesRequest(track_index=track_index, clip_index=clip_index),
    )
```

**Remote Script handler (sync; deferred yield optional):**

```python
def cmd_clear_clip_notes(song, _application, params):
    track_index = _integer_param(params, "track_index")
    clip_index = _integer_param(params, "clip_index")
    track, slot = _clip_slot(song, track_index, clip_index)
    if not bool(_safe(lambda: slot.has_clip, False)):
        raise RemoteError(ERROR_BAD_INPUT, "Clip slot is empty.")
    clip = slot.clip
    if not hasattr(clip, "remove_notes_extended"):
        raise RemoteError(ERROR_WRONG_TYPE, "Clip is not a MIDI clip.")
    clip_length = float(clip.length)
    # Use the same "+1" boundary trick as AbletonBridge so notes at exact length
    # edge are captured and removed.
    before = len(clip.get_notes(0, 0, clip_length + 1, 128))
    clip.remove_notes_extended(0, 128, 0, clip_length + 1)
    # Yield once: remove_notes commits on a UI tick. Skip verify since
    # get_notes re-read is expensive on a 0-note clip; deferred yield is enough.
    return {"notes_removed": before, "track_index": track_index, "clip_index": clip_index}
```

**Why 1 sync call (no `_command_steps` yield):** `remove_notes_extended` is a void op that returns synchronously. The 1-tick cost is paid by the next MCP round-trip. If real-world latency matters, wrap as a generator and yield once — see variant below.

**Generator variant (if tests show latency issue):**

```python
def _clear_clip_notes_steps(song, params):
    # ... same validation ...
    before = len(clip.get_notes(0, 0, clip_length + 1, 128))
    clip.remove_notes_extended(0, 128, 0, clip_length + 1)
    yield
    after = len(clip.get_notes(0, 0, clip_length + 1, 128))
    return {"notes_removed": before - after, ...}
```

**Contract changes:**

- Add `"clear_clip_notes"` to `ALLOWED_MUTATIONS`.
- Register `cmd_clear_clip_notes` in `COMMAND_HANDLERS` (or both if going generator route).
- Re-run `vendor_contracts.py`.

**Tests required:**

- `test_clear_clip_notes` — clip with notes → empty clip → `notes_removed > 0`.
- Empty clip → `notes_removed == 0`.
- Audio clip → `WRONG_TYPE`.
- Empty slot → `BAD_INPUT`.
- `test_packaging.py` bump.

**Risks specific:**

- Live 12.x's `remove_notes_extended` is supported. Live 11.x needs fallback to legacy `remove_notes` (similar to how AbletonBridge's `add_notes_to_clip` has 3 fallback strategies). **Decision: target Live 12+ only**, like the rest of our server.

```python
# Option A: call directly, pass song=track (since song param is unused, type doesn't matter)
```

**Pydantic:**

```python
class SetClipPropertiesRequest(RequestModel):
    track_index: NonNegativeInt
    clip_index: NonNegativeInt
    loop_start: NonNegativeBeat | None = None
    loop_end: PositiveBeat | None = None
    name: Annotated[str, Field(min_length=1, max_length=256)] | None = None

    @model_validator(mode="after")
    def at_least_one(self):
        if self.loop_start is None and self.loop_end is None and self.name is None:
            raise ValueError("At least one of loop_start, loop_end, or name must be provided.")
```

**Remote Script handler sketch (deferred, using `_verified_numeric_steps`):**

```python
def _set_clip_properties_steps(song, params):

        target = _float_param(params, "loop_start", 0.0, 100000.0)
        observed["loop_start"] = (yield from _verified_numeric_steps(
            _safe(lambda: None, song),  # song unused by helper
            attribute="loop_start",
            expected=target,
            result_key="loop_start",
        ))["loop_start"]
        # WAIT: _verified_numeric_steps operates on `song.loop_start`, not clip.loop_start!
        # This helper does NOT support clip attributes. We need a clip-local variant.
```

**⚠ Issue:** `_verified_numeric_steps(song, *, attribute, ...)` writes `song.<attribute>`. For `clip.loop_start` we need a clip-local variant. Two options:

```python
# Option A: refactor _verified_numeric_steps to accept an object instead of song.
def _verified_attribute_numeric_steps(obj, *, attribute, expected, result_key, retries=PLAYHEAD_MOVE_RETRIES):
    actual = float(_safe(lambda: getattr(obj, attribute), -1.0))
    for attempt in range(retries):
        setattr(obj, attribute, expected)
        yield
        actual = float(getattr(obj, attribute))
        if abs(actual - expected) < CUE_TIME_TOLERANCE:
            return {result_key: actual}
    raise RemoteError(ERROR_LIVE_UNAVAILABLE, "Attribute %s did not converge." % attribute)
```

```python
def _find_parameter(track, parameter_name):
    lower = parameter_name.strip().lower()
    mixer = track.mixer_device
    if lower == "volume":
        return mixer.volume
    if lower in ("pan", "panning"):
        return mixer.panning
    import re
    m = re.match(r"^send\s*([a-z])$", lower.replace("_", "").replace(" ", ""))
    if m:
        idx = ord(m.group(1).upper()) - ord("A")
        if 0 <= idx < len(mixer.sends):
            return mixer.sends[idx]
    for device in track.devices:
        for p in device.parameters:
            if p.name.lower() == lower:
                return p
    raise RemoteError(ERROR_BAD_INPUT, "Parameter %r not found on track." % parameter_name)
```

```python
@dataclass
class FakeAutomationPoint:
    time: float
    value: float
    duration: float = 0.0


class FakeAutomationEnvelope:
    def __init__(self, parameter: FakeParameter | None = None) -> None:
        self.parameter = parameter
        self.points: list[FakeAutomationPoint] = []
        self.cleared = False
        self.insert_step_calls: list[tuple[float, float, float]] = []

    def insert_step(self, time: float, duration: float, value: float) -> None:
        self.insert_step_calls.append((time, duration, value))
        # If cleared, replace; otherwise append. Sort by time.
        self.points.append(FakeAutomationPoint(time, value, duration))
        self.points.sort(key=lambda p: p.time)

    def clear(self) -> None:
        self.cleared = True
        self.points.clear()

    def value_at_time(self, t: float) -> float:
        # Linear interpolation
        if not self.points:
            return self.parameter.value if self.parameter else 0.0
        if t <= self.points[0].time:
            return self.points[0].value
        if t >= self.points[-1].time:
            return self.points[-1].value
        for i in range(len(self.points) - 1):
            a, b = self.points[i], self.points[i + 1]
            if a.time <= t <= b.time:
                if b.time == a.time:
                    return b.value
                return a.value + (b.value - a.value) * (t - a.time) / (b.time - a.time)
        return self.points[-1].value
```

## C2. Discoveries from cross-reading the competitor repos

After deeper read of both repos (full scenes.py, full automation.py head + remainder, partial tracks.py, 46KB livewire-lom.js head), the following things are worth knowing:

### From `AbletonBridge/handlers/automation.py`

1. **Held-step automation** is supported via `envelope.insert_step(time, duration>0, value)`. AbletonBridge wraps both breakpoint and step in `create_step_automation`. For our `create_clip_automation` we chose breakpoints (duration=0) to match AbletonBridge's `create_clip_automation`. If we want held steps later, we can add a `duration` field per point (already in their `create_step_automation` signature).
2. **Read APIs** we might want for symmetry later: `get_clip_automation`, `clear_clip_automation`, `list_clip_automated_params`, `get_clip_automation_value`, `get_clip_automation_hires`. Out of v0.4.0 scope but flag for v0.5.0.
3. **`clip.clear_envelope(param)`** is Live 12+. AbletonBridge has explicit `NotImplementedError` if missing. We should mirror that guard.
4. **`track.arrangement_clips` is Live 11+**. Required for `create_track_automation` (NOT in v0.4.0 scope, but flagged for v0.5.0).
5. **Track automation requires an arrangement clip covering the time range.** Falls back to ValueError with full list of clip ranges. Documented pattern.

### From `AbletonBridge/handlers/tracks.py` head

Track properties not exposed by our `get_track_state` that AbletonBridge does expose:

- `track.is_foldable` (group track detection)
- `track.is_grouped`
- `track.group_track` (parent group)
- `track.has_audio_input`, `track.has_midi_input`
- `track.playing_slot_index`, `track.fired_slot_index`
- `track.is_visible`, `track.is_showing_chains`, `track.can_show_chains`
- `track.color` (raw color int, vs `track.color_index` enum)

**Decision: defer to v0.4.x follow-up.** `get_track_state` already returns a comprehensive view (devices, parameters, clip_slots, mixer); adding every LOM property would expand the surface area without obvious agent value. If user feedback demands it, add `get_track_state_extra` (or similar) in v0.5.0.

### From `pnomolos/live-wire/m4l-devices/LiveWire Proxy/livewire-lom.js` (46KB, read head)

This file is the Max `[js]` LiveAPI bridge. **Different runtime from our setup** (they use Max v8/js object; we use Python Remote Script). Patterns to note:

1. **LiveAPI access via `new LiveAPI("app").get("browser")`** — confirms `app.browser` exists in the LOM. **CORRECTION TO EARLIER ANALYSIS**: this is also reachable from Python LOM (`application.browser` is already used in `cmd_get_browser_categories`, line 533 of our own Remote Script). So `search_browser` is viable on TCP. No Extension SDK path needed.
2. **Reference registry pattern**: `refId → LOM path string` map. They have to manage this because of their reflection-based design. We don't — our path-id scheme (`track:N/device:N/param:N`) is server-resolved each call. No port needed.
3. **Dict-based IPC**: `livewire_ipc` named Dict for inter-script communication between `[js]` and `[node.script]`. Not relevant to our architecture.

**Decision: live-wire's lom.js is Max-ecosystem-only. Skip deeper read.**

## D2. Refactor notes (commit #1)

The `_verified_numeric_steps` helper currently takes `song` and writes `song.<attribute>`. It needs to be generalized to take any object. Pattern:

```python
# Old (existing, 3 callers):
def _verified_numeric_steps(song, *, attribute, expected, result_key, retries=PLAYHEAD_MOVE_RETRIES):
    actual = float(_safe(lambda: getattr(song, attribute), -1.0))
    for attempt in range(retries):
        setattr(song, attribute, expected)
        yield
        actual = float(getattr(song, attribute))
        if abs(actual - expected) < CUE_TIME_TOLERANCE:
            return {result_key: actual}
    raise RemoteError(ERROR_LIVE_UNAVAILABLE, "...")

# New:
def _verified_attribute_numeric_steps(obj, *, attribute, expected, result_key, retries=PLAYHEAD_MOVE_RETRIES):
    actual = float(_safe(lambda: getattr(obj, attribute), -1.0))
    for attempt in range(retries):
        setattr(obj, attribute, expected)
        yield
        actual = float(getattr(obj, attribute))
        if abs(actual - expected) < CUE_TIME_TOLERANCE:
            return {result_key: actual}
    raise RemoteError(ERROR_LIVE_UNAVAILABLE, "Attribute %s did not converge." % attribute)

# Backward-compat wrapper:
def _verified_numeric_steps(song, *, attribute, expected, result_key, retries=PLAYHEAD_MOVE_RETRIES):
    return (yield from _verified_attribute_numeric_steps(song, attribute=attribute, expected=expected, result_key=result_key, retries=retries))
```

Same shape for `_verified_boolean_steps` if we want `set_track_property` for non-song attributes later. (We use `_verified_boolean_steps` as-is for `set_track_property` because `setter=` closure captures `track` already.)
