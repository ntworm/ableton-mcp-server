How Model Context Protocol (MCP) Works

MCP is an open standard created by Anthropic for secure, local communication between Large Language Models and desktop development environments. It does NOT run in the cloud — it operates locally over stdio/IPC for maximum privacy and zero latency.

1. Tool Discovery (`tools/list`)

When an MCP client launches `ableton-mcp-server.exe`, it queries `tools/list`. The server returns 65 typed JSON schemas describing all available tools.

2. Local Execution (`tools/call`)

When the LLM decides to manipulate Ableton Live, it issues a `tools/call` JSON-RPC message. The server executes the write loop on Live's local socket and verifies the change.

3. Deterministic Error Feedback

If a parameter write fails or target track is not found, the server returns structured error taxonomies. The LLM parses the error and self-corrects its plan automatically.

Guidelines for driving Ableton Live:
1. Always start by inspecting the project state using `get_session_overview()` or `get_track_list()`.
2. To modify track properties, resolve the target track index using `live_find_track(name_pattern)` first.
3. For parameter adjustments, query parameters via `get_device_list()` and `get_parameter_value()`, then apply changes using `set_parameter_value()`.
4. When executing multiple operations, bundle them using `run_batch(operations)` to ensure atomic execution.
5. Respect the error taxonomy: if you receive `AMBIGUOUS_MATCH` or `VERIFICATION_FAILED`, inspect the track context and retry.

Dual-Bridge System Architecture

Designed specifically to solve cross-platform constraints between Windows host process boundaries, WSL2 network namespaces, and Python concurrency models.

1. TCP JSONL Remote Script (Port 9888)

Low-latency python control surface operating inside Ableton Live's main thread looper. Handles high-frequency parameter mutations, transport commands, clip creation, scene firing, and LOM introspection.

2. WebSocket Extension Host (Port 9889)

Asynchronous WebSocket extension bridge handling complex operations: browser search and device loading, clip warping state, live fade clocking, and batch transaction rollbacks.

Cross-Bridge Error Taxonomy

Agents receive deterministic error codes when a command cannot be executed, allowing LLMs to reason and adapt automatically.

CAPABILITY_UNAVAILABLE

Capability Unavailable

Returned when attempting an operation not supported by the connected Live version or missing extension bridge (e.g., calling warping on an unwarped audio clip).

AMBIGUOUS_MATCH

Ambiguous Match

Returned when a fuzzy track or device lookup matches multiple targets without sufficient specificity. Prompt the agent to supply exact index or full name.

VERIFICATION_FAILED

Verification Failed

Returned by the per-tick write-then-verify loop when a parameter write does not match the readback value from Live's object model after execution.

ACCEPTANCE_GUARD_FAILED

Acceptance Guard Failed

Returned when running destructive or test suite operations against an active project instead of a disposable test Set (e.g. TESTE_CODEX).
