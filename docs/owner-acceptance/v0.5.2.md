## Step 1 — `doctor` round trip + capability matrix (R4)

**Command** (in PowerShell):
```powershell

```

**Expected output keys** (top-level dict, may have others):
- `tools` is a JSON array. **Length MUST be 65.**
- Each entry MUST have these 6 fields: `name`, `domain`, `route`,
  `risk`, `acceptance`, `reversible`. (No field is null or empty.)
- `capability_counts.live_required_tools` MUST be **57** (spec
  records 59 as the original expectation; the drift is documented
  and accepted).
- `capability_counts.public_tools` MUST be 65.
- `capability_counts.routed_commands` MUST be 55.
- `capability_counts.websocket_targets` MUST be 3.
- `capability_counts.read_only_blocked` MUST be 5.
- `capability_counts.feature_flags` MUST be 5.
- `capability_source.catalog` MUST be
  `ableton_mcp_server.catalog:TOOL_CATALOG`.

**Pass:** paste the `capability_counts` block and the
`capability_source` block. A single `len(tools) == 65` print is
sufficient.

**Fail:** paste the full JSON; the test runner will diff against the
canonical `tests/test_capability_matrix.py` expectations.

## Step 4 — R1 `set_tempo` returns `resolved.kind == "tempo"`

**Command** (via the MCP client you use, or directly through
`server.py` from a quick Python REPL):
```python
from ableton_mcp_server.server import set_tempo
import json
result = set_tempo(120.0)
print(json.dumps(result, indent=2, default=str))
```

**Expected output keys** (top-level result):
- `resolved.kind` MUST be `"tempo"`.
- `resolved.tempo` MUST be `120.0` (or very close, after Live
  clamps).
- `resolved.track_name` MUST be **absent** (set_tempo has no track
  context; if a name key shows up here, the field is leaked).
- `resolved.device_name` MUST be **absent**.
- No `resolved` key may have a value of `""` (empty string) — keys
  with empty Live values are **omitted**, not blanked.

**Pass:** paste the full result dict. The drift check is
`"track_name" not in result["resolved"]`.

**Fail:** if `track_name` is present and equal to `""`, the R1
spec was not honoured. Paste the full `resolved` sub-object.

**Fail:** if `track_name` is `""`, paste the result.

## Step 9 — R4 call-time derivation (66th tool experiment)

**Prerequisite:** a feature branch off `main` with one extra tool
appended to `ableton_mcp_server/catalog.py` (and the corresponding
`@mcp.tool()` wrapper in `server.py`).

**Steps:**
1. `git checkout -b owner-acceptance-r4-66tools main`
2. Add a no-op tool:
   ```python
   # in catalog.py, append a new ToolSpec
   ToolSpec(
       name="owner_acceptance_probe",
       domain="meta",
       route=Route.LOCAL,
       risk=Risk.NONE,
       acceptance=AcceptanceMode.OFFLINE,
       reversible=True,
       doc="Owner-acceptance probe; not for production use.",
   )
   ```
3. In `server.py`, add the wrapper:
   ```python
   @mcp.tool()
   def owner_acceptance_probe() -> dict[str, str]:
       """Owner-acceptance probe. Returns its own name."""
       return {"name": "owner_acceptance_probe"}
   ```
4. Reinstall the wheel into `.venv-win`:
   `pip install -e ".[dev]"`
5. Restart Live, restart the MCP server.
6. Re-run Step 1 (`doctor --json`).

**Expected:** `capability_counts.public_tools == 66` AND
`len(tools) == 66`. **No edit to `diagnostics.py` is required.**

**Pass:** the count went up by 1 without touching the
`_capability_counts` function. Delete the branch afterwards
(`git checkout main && git branch -D owner-acceptance-r4-66tools`).

**Fail:** if the count is still 65, the matrix is hardcoded.
Paste the new `capability_counts` and the diff of
`diagnostics.py` (which should be **empty** in the working tree).
